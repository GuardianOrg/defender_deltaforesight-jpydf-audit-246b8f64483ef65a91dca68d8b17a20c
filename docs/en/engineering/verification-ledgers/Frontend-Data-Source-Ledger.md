# Frontend Data Source Ledger

Purpose: progressively remove mock data, stale snapshots, and upstream Liquity API fallbacks from the frontend production surface, and make JPY DeFi contracts / subgraph / backend / ops exporters the source of truth.

## Classification Criteria

| Category | Treatment |
| --- | --- |
| Production data | Numbers and state used by users or operators for decisions. Must use contracts, subgraph, backend, or ops exporter as the source. |
| Local-only data | Values for `local-stack`, tests, or fixtures. Must not be a production build default. |
| UI fallback | Loading, empty, and error states. Allowed as long as they do not fill in estimated balances, APR, or other numeric values. |

## CI Guard

`frontend/app/scripts/check-production-data-sources.ts` scans `frontend/app`, `frontend/console/src`, `frontend/console/scripts`, `frontend/ops/src`, and `frontend/ops/scripts` for:

- `api.liquity.org` references in the `frontend/app` production surface
- reintroduction of the old stats fallback through `NEXT_PUBLIC_LIQUITY_STATS_URL`
- root `frontend/app/public/*snapshot*.json`
- root-path references to `/initiatives-snapshot-*.json` or `/troves-snapshot-*.json`
- direct product-documentation URLs that bypass `frontend/app/src/docs-url.ts` (except the explicitly allowlisted devnet operations guide)

This guard is intentionally narrow. It does not flag words such as `fixture` or loading fallback. The mock-data removal scope is production numeric/state sources only.
