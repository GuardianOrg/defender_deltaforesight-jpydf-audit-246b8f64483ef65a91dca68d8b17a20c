# Frontend Development Plan

> **Implementation plan and progress tracker for the three jpydf-v2 frontend surfaces.**
> The source of truth for requirements is [../Frontend.md](../../protocol/product/spec/Frontend.md) (`FRNT-*` IDs). This document only covers implementation decomposition, decision records, and local verification procedures, and does not redefine requirements (FRNT-GOV-003).
> Progress status legend is the same as [Development-Plan.md](Development-Plan.md) (✅ Completed / 🟢 Implemented / 🟡 In progress / 🔴 Not started).

---

## 0. Scope and Principles

- **Targets**: (A) user app `frontend/app` (minimal-diff fork of the upstream Liquity v2 app) / (B) administrator console `frontend/console` (new) / (C) operations dashboard `frontend/ops` (new).
- **First milestone**: all three surfaces run against real data in the local environment (anvil + Phase 4 dToken-wired deployment), and the main flows can be verified e2e (Frontend.md §13, "treat e2e-local as a first-class acceptance method").
- **Minimal upstream modification** (FE Principle 1): keep (A) as a fork of the upstream Liquity v2 app, but normalize JPYdf-owned frontend surfaces (display copy, types, request schemas, local storage keys, query keys, flow IDs, etc.) to JPYdf naming. Upstream package names, vendor component names, and base protocol spec references are outside this replacement scope. Maintain an update-friendly shape for pulling upstream changes.

## 2. Local Stack (Reproduction Steps)

```bash
# 1. Chain
anvil --port 8545 --chain-id 31337 --base-fee 0 --gas-limit 60000000

# 2. Deploy + Multicall3 injection + demo data + app env generation + (B)(C) binding generation
cd contracts && ./utils/local-stack.sh

# 3. User app (A)  http://localhost:3000
cd frontend/app && pnpm build-deps && pnpm dev   # a local URL falls back to the repo schema; check runtime data after the subgraph syncs
# To validate just query/schema in a separate output:
# SUBGRAPH_SCHEMA_FILE=../../subgraph/schema.graphql GRAPHQL_CODEGEN_OUT=/tmp/jpydf-app-graphql-codegen/ pnpm build-graphql

# 4. Administrator console (B)  http://localhost:3001
cd frontend/console && pnpm dev

# 5. Operations dashboard (C)  http://localhost:3002
cd frontend/ops && pnpm dev
```

- `local-stack.sh` breakdown: `DeployLiquity2Script` (8-branch dToken wiring, production feed/Strategy code + mock data sources) → inject Multicall3 runtime code at the canonical address via `anvil_setCode` → `SeedLocalDemo` (faucet mint → Vault deposit → 13 troves → SP deposit → allocate → one delayed redemption queue item) → generate `.env.local` → generate df-shared.
- Active-branch demo prices: dwstETH ≈ ¥600,000.6 / dUSDC ≈ ¥150 (USD/JPY ≈ 150).

## 4. Operations Notes (Known Local Environment Behavior)

1. **anvil tx dropping**: with bursty forge broadcast, some txs silently disappear from the pool (measured: 58 of 336 txs). `--slow` resolves this. Also pin base fee to 0 (prevents maxFee shortages caused by EIP-1559 spiraling).
2. **The demo trove path has been removed from `./deploy`**. Seed local demo data with `SeedLocalDemo`.
3. **Multicall3**: the current deploy script does not deploy Multicall3 locally, so `local-stack.sh` injects runtime code at the canonical address (required for the app's batched reads).
4. **wagmi reconnect**: the dev wallet connector can remain stuck in `connecting` after page reload; an auto-promotion path is added only when the dev wallet is enabled (`services/Ethereum.tsx`).
5. **claim eligibility is based on chain time**: using wall-clock time diverges from local time warps (measured bug → fixed). `useWithdrawRequests` returns `ready` from the latest block timestamp.
6. **Impact of no subgraph**: transaction history, average interest, interest distribution histograms, and other list-style views show "…". All operation surfaces backed by RPC work.

- 🟡 **FRNT-FR-010 / FRNT-TBD-008**: externalizing display strings into a text catalog (ja/en) remains open. - 🔴 **FRNT-FR-020**: local alternative for transaction-history screens that assume a subgraph (run graph-node or add a lightweight indexer).
- 🔴 **FRNT-FR-021 requirement 3**: configuration framework for geoblocking, etc. (keep default disabled).
- 🔴 **FRNT-EVT-***: telemetry and synthetic monitoring (after production hosting is finalized).
- 🟡 **FRNT-TBD-004**: Public health JSON is implemented through `frontend/ops export-stats`, and `frontend/app` can read it through `NEXT_PUBLIC_PROTOCOL_STATS_URL`. Production hosting/company ownership/runtime health moves to `Frontend-Production-Delivery-Gate.md` evidence. Remaining product work: APR time-series collector.
- 🔴 **FRNT-FR-013 / FRNT-FR-014**: `CollateralYieldZapper` deploy manifest, `df-shared` binding, app env, and the concrete Sky USDC-to-USDS converter are implemented. Remaining work is user app adoption, `SkyUsdcSUsdsYieldZapper` deploy manifest / `df-shared` binding / app env, and JPYdf swap route review. The current upstream-style `Leverage*Zapper` multi-step path is a local fallback, not completion of production 1-tx aggregation or Underlying-denominated close/withdraw.
- 🟡 **FRNT-TBD-007**: Production domain / hosting has a defined gate in [Frontend-Production-Delivery-Gate.md](../../contributors/deltaforesight/delivery-plans/Frontend-Production-Delivery-Gate.md). Remaining work is concrete domain / account / endpoint / monitor / rollback evidence collection.
- 🟡 **FRNT-TBD-009**: Mobile / in-wallet browser support has a defined gate in [Frontend-UX-Readiness-Gate.md](../../contributors/deltaforesight/delivery-plans/Frontend-UX-Readiness-Gate.md). Remaining work is viewport / wallet modal / tx confirmation / failure state evidence collection.
- 🟡 **FRNT-TBD-006**: mirror delivery is not adopted on Day-1; the Day-2 optional gate is defined in [Frontend-Mirror-Delivery-Policy.md](../../contributors/deltaforesight/delivery-plans/Frontend-Mirror-Delivery-Policy.md). Remaining work is collecting concrete mirror URL / CID / ENS / domain allowlist / incident announcement / rollback evidence.
- 🔴 Multiply enablement conditions (FRNT-TBD-002).
- 🔴 **Remove accidental RPC default calls**: local logs show failed CORS calls to `eth.merkle.io` (viem's default mainnet RPC). Even if this is only a local symptom, in production it becomes an RPC outage path, vendor leakage, and user-visible error. Treat it as a mainnet blocker: production build / runtime health checks fail closed if official RPC config is missing or any reachable path can fall back to viem's public default.
- 🟡 **Full grep audit** of BOLD→JPYdf normalization for display copy and owned data models (FRNT-FR-011 completion criterion): reachable screens are replaced. If disabled upstream-derived screens are reintroduced, define a separate spec / route config / UI copy first and do not retain old BOLD or upstream staking wording.
