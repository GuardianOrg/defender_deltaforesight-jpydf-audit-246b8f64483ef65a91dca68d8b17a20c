# Mainnet Fork Stress Gate

This runbook defines the self-operated gate for mainnet launch rehearsals using
an archive RPC, Foundry / Anvil forks, AWS CodeBuild, and KMS-encrypted S3
artifacts. It covers planned deploy / handover / launch operations and historical
or synthetic stress scenarios without depending on a third-party simulation SaaS.

The Japanese version is the source of truth. This document supports
[Mainnet-Deploy-Env-Freeze-Runbook.md](Mainnet-Deploy-Env-Freeze-Runbook.md),
[Mainnet-Governance-Handover-Runbook.md](Mainnet-Governance-Handover-Runbook.md),
[Mainnet-Fork-Stress-Scenario-Package.md](Mainnet-Fork-Stress-Scenario-Package.md),
[Frontend-Production-Delivery-Gate.md](../../../contributors/deltaforesight/delivery-plans/Frontend-Production-Delivery-Gate.md),
and [Admin-Console-Production-Gate.md](../../../contributors/deltaforesight/delivery-plans/Admin-Console-Production-Gate.md). It
does not replace direct RPC reads, handover verification, or frontend production
gates.

## 1. Scope

In scope:

- `mainnet-fork-evidence` against pinned Ethereum mainnet blocks.
- Fork rehearsal for Day-1 governance / operations transactions executed by Safe
  or role holders.
- Payload-hash matching for privileged calldata generated by the admin console.
- Launch-window rehearsals for SP seed, JPYdf/USDC Uniswap v4 liquidity,
  bootstrap Troves, redemption / liquidation readiness, and strategy operations.
- Stress checks for oracle behavior, DEX liquidity, Aave reserves, liquidation /
  redemption, gas congestion, and external protocol availability.
- Reproducible evidence through AWS CodeBuild and S3 artifacts.

Out of scope:

- Making an external simulation SaaS a required launch dependency.
- Recording private keys, raw `MAINNET_RPC_URL`, AWS secrets, or unpublished Safe
  nonces in evidence.
- Automatically sending production transactions.
- Treating a block that predates required Day-1 external dependencies as a full
  deploy rehearsal.

## 2. Gate Positioning

| Layer               | Primary gate                                        | Fork stress gate check                                                             |
| ------------------- | --------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Deploy env freeze   | External address / manifest freeze                  | Deploy and manifest preflight pass with the same commit / env / pinned block       |
| Governance handover | Handover dry-run / accept / verify                  | Prepare and pending-owner verify pass on the fork                                  |
| Launch operation    | SP seed / LP / redemption / liquidator direct reads | Launch operation config is consistent with fork state                              |
| Frontend app / ops  | Hosting env / data source / stale-state gate        | Public write-flow and ops-action calldata / routes are readable against fork state |
| Admin console       | Auth / noindex / Safe boundary / calldata export    | Exported calldata hash matches the rehearsal input hash                            |
| Risk parameters     | `Parameters.md` and risk-owner sign-off             | Historical / synthetic stress rechecks MCR / LLTV / caps / route gates             |

Business / risk reviewers should be able to confirm:

- Which launch stage / risk family the scenario belongs to.
- Whether `commit`, `FORK_BLOCK`, manifest hash, and launch config hash are fixed.
- Whether expected and actual status match.
- Which parts ran: deploy, handover, launch operation, frontend route.
- Whether the stress block is after required Day-1 dependencies existed.
- Whether evidence is stored as an AWS-managed artifact and contains no secrets.

## 3. Required Scenario Set

| Scenario                                      | Required                          | Notes                                                                                                                                                                                             |
| --------------------------------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Current freeze block baseline                 | Must                              | Full deploy / handover / manifest preflight at the freeze block                                                                                                                                   |
| Launch operation rehearsal                    | Must                              | SP seed, JPYdf/USDC liquidity, bootstrap Trove, redemption / liquidation readiness                                                                                                                |
| Governance / owner handover                   | Must                              | Pending owner / role holder / Timelock delay verification                                                                                                                                         |
| Stablecoin depeg family                       | Must                              | USDC price, liquidity, and reserve assumptions                                                                                                                              |

| Vault buffer / allocator / strategy controls  | Must                              | withdrawDelay, bufferTargetBps / floor, allocateMaxMove / cooldown, strategy weight / cap, paused/frozen upstream failure modes, and backingRatio visibility                                      |

| Aave reserve stress                           | Must when Aave strategy is active | Frozen / paused / supply cap / liquidity shortage by fork or targeted test                                                                                                                        |
| Liquidator dry-run                            | Separate gate                     | Canonical evidence stays in the launch operation and bot runbooks                                                                                                                                 |
| User app public write-flow sample             | Should                            | Representative borrow / adjust / redeem / SP deposit / vault redeem calldata                                                                                                                      |

Do not hardcode scenario blocks in this document. For every rehearsal, the risk
owner records `DF_STRESS_SCENARIO_ID`, `FORK_BLOCK`, scope, exclusions, and
artifact id in evidence.
Use
[`Mainnet-Fork-Stress-Scenario-Package.md`](Mainnet-Fork-Stress-Scenario-Package.md)
for the scenario ids, matrix, business summary, and secret-hygiene package
format. Before sign-off, strict validation requires `risk_owner_signoff` for
each executed scenario and `exclusion_reason` for any non-smoke scenario that
does not count as full deployment rehearsal evidence.

For old crisis events:

- Full deploy rehearsal is valid only when all Day-1 external dependencies exist
  at the chosen block.
- If dependencies do not exist at that block, use the old block only for
  target-asset / target-protocol observation and cover the rest with current-fork
  synthetic stress, unit / invariant tests, or targeted fork tests.
- `latest` is acceptable for smoke only. Mainnet launch evidence requires a
  pinned block.

## 4. AWS Execution Policy

Production evidence should not be created only on an operator's local machine.
Place at least these boundaries in AWS:

- GitHub Actions assumes an AWS role through OIDC, starts CodeBuild, and waits
  for build status.
- CodeBuild / GitHub Actions OIDC / deployment roles live in company-managed AWS
  accounts.
- `MAINNET_RPC_URL` is archive-capable and is read from AWS Secrets Manager or
  SSM Parameter Store. Do not store it in GitHub repository / environment
  secrets.
- Frozen `DEPLOYER` / `DF_*` deploy env is stored in a Secrets Manager env-file
  secret and exported in CodeBuild as literal `KEY=value` entries. Do not put
  private keys, raw RPC URLs, or unpublished Safe nonces in this secret.
- `DEPLOYER` is a public address used for Anvil impersonation, not a private key.
- The CodeBuild image provides `forge`, `anvil`, `cast`, Git, Node, and pnpm.
  Versions are recorded in evidence.
- CodeBuild logs and artifacts do not expose raw secrets, raw RPC URLs, private
  keys, or Safe nonces.
- `mainnet-fork-stress-evidence/**` is stored in a KMS-encrypted S3 bucket.
- Evidence records build id, commit, scenario id, fork block, manifest hash,
  launch config hash, operator label, and artifact bucket label.

The standard CDK backend configuration creates:

| Resource                          | Purpose                                             | Boundary                                                                                                                                  |
| --------------------------------- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `ForkStressGateProjectName`       | CodeBuild project that runs `mainnet-fork-evidence` | Uses `infra/cdk/buildspecs/mainnet-fork-stress-gate.yml`; reads `MAINNET_RPC_URL` and the frozen deploy env file from Secrets Manager     |
| `ForkStressEvidenceBucketName`    | Evidence artifact bucket                            | Block Public Access, versioning, SSE-KMS                                                                                                  |
| `ForkStressGithubDispatchRoleArn` | GitHub Actions OIDC dispatch role                   | Trust is pinned to `aud=sts.amazonaws.com` and repo/ref subject; permissions are only `codebuild:StartBuild` / `codebuild:BatchGetBuilds` |

Keep the CDK deploy role and fork stress dispatch role separate. The dispatch
role must not receive CloudFormation, IAM, S3 bucket administration, or Secrets
Manager write permissions.

## 5. Experiment Ladder

| Phase                                  | Purpose                                                               | Go condition                                                          |
| -------------------------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Phase 0: local current-block smoke     | Confirm env and `mainnet-fork-evidence` basics                        | Deploy / manifest preflight pass with `--skip-handover`               |
| Phase 1: GitHub OIDC dispatch smoke    | Confirm GitHub can start CodeBuild using only an AWS OIDC role        | GitHub stores no RPC secret and returns a CodeBuild build id / status |
| Phase 2: single pinned block rehearsal | Confirm full deploy / handover / launch operation at the freeze block | Pass without `--skip-handover`; artifact lands in S3                  |
| Phase 3: historical / synthetic matrix | Check stress scenarios by risk family                                 | Every scenario has pass / fail / accepted exception and owner         |
| Phase 4: pre-launch final rerun        | Rerun with final freeze commit / config / block                       | No No-Go condition remains                                            |

Do not commit production rehearsal configs to the repository. Store them in the
evidence bucket with the Safe / console artifact, deployment manifest hash,
launch operation config hash, and AWS build id. Use the package layout and
scenario matrix in
[`Mainnet-Fork-Stress-Scenario-Package.md`](Mainnet-Fork-Stress-Scenario-Package.md).

## 6. Standard Commands

Scenario package scaffold:

```bash
cd contracts
pnpm mainnet-fork-stress-package:init \
  --out /path/to/evidence-dir/mainnet-fork-stress-evidence
pnpm mainnet-fork-stress-package:check \
  --package /path/to/evidence-dir/mainnet-fork-stress-evidence \
  --allow-placeholders
```

Local smoke:

```bash
cd contracts
pnpm mainnet-fork-evidence \
  --out /tmp/jpydf-mainnet-fork-stress-baseline \
  --skip-handover
```

Full rehearsal:

```bash
cd contracts
DF_LAUNCH_OPERATION_CONFIG=/path/to/mainnet-launch-operation.config.json \
pnpm mainnet-fork-evidence \
  --out /path/to/evidence-dir/mainnet-fork-stress
```

Run artifact import:

```bash
cd contracts
pnpm mainnet-fork-stress-package:import-run \
  --package /path/to/evidence-dir/mainnet-fork-stress-evidence \
  --run /path/to/evidence-dir/mainnet-fork-stress \
  --scenario baseline-freeze-full \
  --actual-result pass \
  --full-deploy-eligible true \
  --codebuild-status SUCCEEDED
```

The import updates only safe metadata in `scenario-matrix.*`,
`codebuild-runs.csv`, and the scenario README. Do not paste raw logs, raw RPC
URLs, or raw privileged calldata into public summaries.

Manual GitHub Actions entrypoint:

```bash
gh workflow run mainnet-fork-stress-gate.yml \
  --repo deltaforesight/jpydf-v2 \
  -f fork_block=<pinned-mainnet-block> \
  -f scenario_id=baseline-current \
  -f skip_handover=false \
  -f aws_region=ap-northeast-1 \
  -f aws_role_to_assume=arn:aws:iam::<account-id>:role/<github-oidc-codebuild-dispatch-role> \
  -f codebuild_project=<jpydf-mainnet-fork-stress-project>
```

Use the CDK outputs `ForkStressGithubDispatchRoleArn` and
`ForkStressGateProjectName` for `aws_role_to_assume` and `codebuild_project`.

Pre sign-off package check:

```bash
cd contracts
pnpm mainnet-fork-stress-package:check \
  --package /path/to/evidence-dir/mainnet-fork-stress-evidence
```

AWS CodeBuild entrypoints:

- `.github/workflows/mainnet-fork-stress-gate.yml`
- `infra/cdk/buildspecs/mainnet-fork-stress-gate.yml`
- `FORK_BLOCK` is a decimal mainnet block number.
- `DF_STRESS_SCENARIO_ID` is path-safe.
- `DF_STRESS_SKIP_HANDOVER` is `false` for production final rehearsal.
- `DF_LAUNCH_OPERATION_CONFIG` is optional.
- The CodeBuild project allows the GitHub OIDC dispatch role only
  `codebuild:StartBuild` / `codebuild:BatchGetBuilds`.

Main CDK settings:

| Setting                                      | Required when          | Notes                                                                                                                                                                                                                                  |
| -------------------------------------------- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `JPYDF_FORK_STRESS_ENABLED=true`             | Creating the AWS gate  | Also requires `JPYDF_BACKEND_ENABLED=true`                                                                                                                                                                                             |
| `JPYDF_FORK_STRESS_BUILD_IMAGE`              | Fork stress is enabled | Must include `forge`, `anvil`, `cast`, Git, Node, and pnpm. Production requires a digest                                                                                                                                               |
| `JPYDF_FORK_STRESS_MAINNET_RPC_SECRET_ARN`   | Fork stress is enabled | Secrets Manager ARN containing the archive-capable RPC URL                                                                                                                                                                             |
| `JPYDF_FORK_STRESS_DEPLOY_ENV_SECRET_ARN`    | Fork stress is enabled | Secrets Manager ARN containing frozen `DEPLOYER` / `DF_*` / `DEPLOYMENT_MODE` / `SALT` / `GAS_ESTIMATE_MULTIPLIER` env-file contents as literal `KEY=value`. `export` lines, private keys, raw RPC URLs, and Safe nonces are forbidden |
| `JPYDF_FORK_STRESS_GITHUB_OIDC_PROVIDER_ARN` | Fork stress is enabled | ARN for `token.actions.githubusercontent.com`                                                                                                                                                                                          |
| `JPYDF_FORK_STRESS_GITHUB_REPOSITORY`        | Optional               | Default `deltaforesight/jpydf-v2`                                                                                                                                                                                                      |
| `JPYDF_FORK_STRESS_GITHUB_REF_PATTERN`       | Optional               | Default `repo:deltaforesight/jpydf-v2:ref:refs/heads/develop`; config rejects repository mismatch and non-branch/tag subjects                                                                                                          |

The `JPYDF_FORK_STRESS_DEPLOY_ENV_SECRET_ARN` value is not sourced as a shell
script. Remove `export` from the `Mainnet-Deploy-Env-Freeze-Runbook.md`
skeleton and store only literal `KEY=value` entries for `DF_*`, `DEPLOYER`,
`DEPLOYMENT_MODE`, `SALT`, and `GAS_ESTIMATE_MULTIPLIER`. The buildspec rejects
key names containing `*PRIVATE*`, `*SECRET*`, `*MNEMONIC*`, or `*RPC*`. Do not
include private keys, raw RPC URLs, or unpublished Safe nonces.

Required secrets / env:

| Variable                           | Purpose                                                | Evidence treatment                                                                                                      |
| ---------------------------------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| `MAINNET_RPC_URL`                  | Archive-capable fork source                            | Raw URL is forbidden                                                                                                    |
| `DF_DEPLOY_ENV_FILE`               | Frozen deploy env literal from Secrets Manager         | Raw content is forbidden; allowed keys are `DF_*`, `DEPLOYER`, `DEPLOYMENT_MODE`, `SALT`, and `GAS_ESTIMATE_MULTIPLIER` |
| `FORK_BLOCK` / `FORK_BLOCK_NUMBER` | Pinned block                                           | Required in evidence                                                                                                    |
| `DEPLOYER`                         | Public address for Anvil impersonation                 | May be shown                                                                                                            |
| `DF_*` deploy env                  | Deploy / handover / strategy / launch operation config | Secret values forbidden; addresses / hashes allowed                                                                     |
| `DF_LAUNCH_OPERATION_CONFIG`       | Launch operation config                                | Path / config hash allowed                                                                                              |
| `DF_STRESS_SCENARIO_ID`            | Stress scenario id                                     | Required in evidence                                                                                                    |

Outputs:

- `evidence-summary.txt`
- Step-level `*.cmd` / `*.log`
- `deployment-manifest.json`
- `deployment-manifest.sha256`
- Optional `deployment-context-latest.json`

## 7. No-Go Conditions

Do not proceed to mainnet public launch or privileged execution if any of these
remain true:

- Full rehearsal cannot be reproduced against a pinned block.
- Deploy, manifest preflight, handover verify, or launch operation check has an
  unexplained failure.
- The target `to` / value / calldata hash does not match the Safe artifact or
  console export.
- Evidence uses `latest`, old generated bindings, or an old launch config.
- Only local temporary output exists; no AWS-managed artifact exists.
- Evidence or PR text includes raw RPC URLs, AWS secrets, private keys, or
  unpublished Safe nonces.
- A Day-1 out-of-scope Curve / Balancer / Uniswap v3 / USDT direct route remains
  in the scenario plan.
- A historical block predates required Day-1 dependencies but is treated as a
  full deploy rehearsal pass.
- A fail / warn is treated as Go without an explicit risk-owner exception.

## 9. How To Read The Result

| Status | Meaning                                                                                       | Launch decision                                                 |
| ------ | --------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `pass` | Deploy / handover / launch operation / stress checks passed as expected                       | Go is possible if the other gates also pass                     |
| `warn` | Limited historical block, missing dependency, gas unavailable, or another item needs judgment | Generally No-Go for mainnet evidence unless explicitly excepted |
| `fail` | Expected status mismatch, secret leak, Safe nonce exposure, or required evidence missing      | No-Go                                                           |

Detailed logs may be retained as internal artifacts, but business / public
summaries must not contain raw calldata, secrets, or private endpoints.
