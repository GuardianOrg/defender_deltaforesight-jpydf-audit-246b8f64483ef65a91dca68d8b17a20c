## Reproduction and impact decision

`CollateralVault.claim(requestId)` is intentionally permissionless and always
pays the recorded request owner. A third party can observe an owner's matured
claim transaction and settle the same request first. The front-runner receives
nothing and the owner receives the full amount exactly once, but the owner's
later transaction previously reverted with `RequestNotFound` because the
request was already marked claimed.

The report correctly identifies a low-severity transaction-status and UX grief.
It does not expose theft, redirection, double payment, stranded entitlement, or
accounting loss. The report's stronger implication that idempotence removes the
owner's gas cost is not accepted: a transaction that reaches execution still
consumes gas even if the function returns `0` rather than reverting.

The pre-fix mutation run restored the old settled-request revert. The new
`test_Claim_FrontRunSettlementMakesOwnerRetryIdempotent` then failed with
`RequestNotFound`; it passed after remediation.

## Remediation

The existence check remains first. An unissued request ID therefore continues
to revert with `RequestNotFound`. Once a real request has been settled,
`claim()` now returns `0` before the time, buffer, accounting, transfer, and
event paths.

The change deliberately preserves:

- permissionless settlement;
- payout fixed to the stored request owner;
- one successful transfer and one `pendingWithdrawals` decrement;
- no event on an idempotent retry;
- rollback of `claimed` and accounting if the first transfer fails;
- `pausedClaim` and `nonReentrant` protection on every call.

An owner-only claim was not reintroduced because that would recreate the
contract-receiver liveness defect fixed by source commit `02bc91f8`. A claimer
fee was not added because paying the request owner does not reimburse the
front-run victim, and a caller incentive would add token-accounting and
front-running complexity outside this finding.

## Residual risk

- An already-submitted owner transaction still spends gas when it executes as
  a successful no-op. Avoiding that cost requires wallet/relayer replacement,
  cancellation, private-ordering, or off-chain state refresh; the Vault cannot
  refund it without a materially different economic design.
- A caller can still choose which matured request to settle first, but cannot
  change the beneficiary or amount. The existing `pausedClaim` incident control
  and fixed-payout semantics are unchanged.
- Callers that treated `RequestNotFound` on double claim as a completion signal
  must instead accept the documented zero return. The ABI selector and return
  type are unchanged.

The [differential security review](../reviews/l-01-differential-review.md) found
no blocking issue or additional regression.
