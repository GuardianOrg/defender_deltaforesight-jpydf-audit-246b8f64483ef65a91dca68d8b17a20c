## Reproduction and impact decision

`fetchJpyUsdRate()` returned immediately whenever `jpyFreezeExpired` was true.
That made its fresh-response branch unreachable after one freeze exceeded
`MAX_JPY_FREEZE_DURATION`. The provider has no setter or upgrade path, and every
active branch shares it, so a transient JPY/USD outage became a deployment-wide
permanent availability failure even after Chainlink published a fresh rate.

The report's root cause and Medium availability classification are accepted.
The path is fail-closed: it does not serve the recovered rate incorrectly or
redirect funds. The impact is persistent borrowing/redemption shutdown and the
need to replace the provider and feed sources operationally.

## Remediation

The provider now attempts the Chainlink read before applying the expiry
shortcut. A fresh response:

1. adopts the recovered rate and its exact `updatedAt`;
2. clears `jpyFrozenSince` and `jpyFreezeExpired`;
3. emits `JpyRateUnfrozen` and begins a new healthy episode.

An unhealthy response while expired still returns the latched rate with
`freezeExpired = true`. The fix therefore restores liveness without weakening
the 24-hour safety bound for the current outage.

Branch-local terminal state is deliberately not reversed. A branch that already
observed expiry remains pinned at `lastGoodPrice`; a branch that did not observe
expiry and remains on `primary` can resume the fresh shared rate. A later outage
starts a new freeze episode and can expire independently.

Before the production change, the new fresh-recovery and later-outage tests
failed against the report identity. After the change, the focused provider,
composite feed, shared-latch, and proxy suites passed 68/68 tests. The standard
Foundry PR gate passed 1,543/1,543 tests across 81 suites; production-size,
format, patch-hash, snapshot-reconstruction, and maintainer-checkout gates also
passed. The
[differential security review](../reviews/m-01-differential-review.md) found no
blocking issue or additional regression.

## Side-effect review

- No storage variable, type, or order changes.
- Constructor, oracle binding, staleness threshold, and 24-hour maximum remain unchanged.
- Invalid, stale, reverting, and gas-griefing response validation remains unchanged.
- Existing branch shutdown is not automatically reversed by provider recovery.
- JP normative requirements, EN support text, verification ledger, and incident policy now describe expiry as per-episode state.
